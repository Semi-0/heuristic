# Reranked dependency context

Queued at 01:56 UTC on November 27, after the four-way prompt experiment. Six matched historical and revised orders use the recorded definitions and quantities from the November 26 reuse experiment. Qwen3-Reranker-0.6B scores the label and body of every archived record against the exact speaker question, with one fixed instruction. Top-one selection is fixed before evaluation. The harness expands the selected record's transitive Datomic parents and sends the ordered evidence to the existing Flash xhigh solver. Further reads are available and counted. The expected answer and gold dependency IDs are available only to the scorer.

CPU ranker weights e61197ed45024b0ed8a2d74b80b4d909f1255473, PyTorch 2.8.0, Transformers 4.57.3, bfloat16 and two threads. The worker uses the official yes/no logit comparison. Timing records per-question ranking, end-to-end request time and cold model loading separately. Context assembly and compiler scoring are included in total time. The solver and compiler settings match the [original reuse trial](2026-11-26-reuse-context.md). Earlier conditions are historical comparisons. [Ranker](../experiments/dependency-context/reranker.py) and [dispatcher](../experiments/dependency-context/rerank.clj).

Set LAIN_RERANK_MODEL to the pinned local model directory and LAIN_RERANK_PYTHON to a Python interpreter with the pinned packages. Run `experiments/dependency-context/run.sh rerank /absolute/new/report-directory /absolute/original/reuse-report`.

At 01:58 UTC the matched Qwen3-Reranker-4B test was added after the 0.6B run, with weights 22e683669bc0f0bd69640a1354a6d0aebcfeede5. Both rankers use the same CPU dtype, threads, instruction, candidate ordering, batch size, top-one expansion and Flash settings. Ranking probabilities are computed in float32.

At 02:02 UTC a third job was queued behind fixed-effort 4B. The same 4B worker first ranks dependencies, then scores three prespecified reasoning-effort descriptions against the question and retrieved evidence. The highest-scoring label sets Flash's reasoning_effort for that question, including any subsequent reads. Route timing, class scores, token counts and selected level are saved. The live Flash tokenizer rendered different inputs for the same text at low, medium and xhigh (44, 14 and 56 tokens). This establishes that the setting reaches its prompt template. The six fixed and adaptive 4B runs use the same input cases and graph; no labels are fitted using the answer key.

Compare speed and accuracy within a case family. The six order questions span three setups and two revisions of one workflow. The four order/meter questions use a separate counterbalanced protocol. Means include every failed attempt; generated tokens include reasoning and are summed across each row. Timings exclude shared setup and worker startup. The three original order baselines were recorded the previous day; fixed and adaptive ranker runs were sequential with stochastic Flash output.

Both classifiers selected the correct source record on all six orders. The two 4B conditions produced identical candidate scores and evidence IDs on every paired question. The 0.6B ranker averaged 15.3 seconds to rank all records, compared with 56.6 seconds for fixed 4B. Flash averaged 58.1 and 55.8 seconds respectively. Both finished with six supported correct answers. The 4B adaptive worker spent 57.1 seconds ranking and another 20.1 seconds choosing effort on average. It chose medium on all six cases. Flash generation averaged 24.0 seconds. Relative to fixed 4B, mean total latency fell from 112.4 to 101.1 seconds and median latency rose from 99.6 to 100.6 seconds. Supported correctness fell from 6/6 to 0/6. Four adaptive answers applied a tariff directly to bundles, bypassing the sheet conversion, and two emitted invalid Lain expressions. The experiment establishes performance for these particular outputs and this routing rubric. It does not isolate the effect of reasoning effort from all other stochastic generation differences.
