# Durable executable reuse from saved Lain source

The user selected source-based restoration: store Lain code and its dependencies,
then compile those definitions into a fresh environment after process termination.
This experiment implements that choice without serializing a live graph or
changing the kernel, main runtime, model implementation, or deployed service.

## Result

The real-model trial `runtime/durable-20261110/live-2-frozen` passed all 14
acceptance checks. The original model-written event-cost closure and its two
callable dependencies were recovered from the previous cumulative experiment's
closed Datomic database, not regenerated by a model.

## What is stored and rebuilt

`src/lain_harness/source_restore.clj` reads the existing chunked source and
admission evidence from Datomic. Starting at the selected public catalog id, it
follows named definition dependencies and literal `catalog:resolve` dependencies.
It handles the `network` parameters and sequential `let` bindings used by this
example so local names are not mistaken for captured globals.

Every selected form must match a successful recorded admission exactly. The
bundle preserves its original source slice, source index, module identity,
original artifact hash, and new module hash. The recorded definitions selected
in this trial were:

- Library forms 0, 1, 4, 5: two callable definitions and their registrations.
- Composition forms 0, 1, 2, 3, 8, 9: two catalog references, their observed
  callable values, the composed network definition, and its registration.

Old example executions, old order applications, reply connections, discovery
queries, model requests and unrelated maximum/legacy callables are excluded.
The old database is copied only after its originating process is closed; the
original evidence database is preserved. The two trial JVMs operate sequentially
on that working copy. The first prepares and verifies the minimal bundle; the
second reads it from the database without reading the old trial's source files.

Registrations reconnect persistent public catalog identities to new live cell
references. The original catalog metadata remains unchanged. The fresh model
receives environment documentation and query results, not the restored
implementation text. Its generated query and invocation are admitted through the
existing runtime into separate lexical children.

## Orchestration and failure investigation

`experiments/catalog-durable.lain` owns restoration ordering and model-stage
transitions. It uses the existing `incremental-compile` completed-source boundary
for archived definitions and the existing `runtime` for new model output. Native
adapters read/validate stored artifacts, perform ordinary database operations and
observe outcomes. The shell controls process creation and termination; the host
probe supplies inputs and evaluates results. Neither chooses model replies or
maintains a second agent loop.

The first attempt admitted the library's four forms but did not advance to the
composed closure. A bounded diagnostic confirmed the complete library receipt
was available while downstream status use remained unresolved. Applying the
existing `cell:first` completed-value pattern before projecting admission status
resolved this handoff. Both the preparation and reopening processes then passed.
This is an experiment wiring correction; the kernel was not patched. The initial
unbounded attempt was stopped, and the diagnostic attempt closed on timeout.
Neither made a provider call. Root cause beyond this observed projection behavior
was not established by this experiment.

## Scope and verification

This is **durable source reconstruction**, not resumption of exact suspended
cell state. New runtime identities are expected. The result establishes reuse of
these saved definitions and captured callable dependencies after termination.
It does not establish general restoration of arbitrary native capabilities,
resources, active external effects, cyclic definitions, or TTMS state.

The dependency collector intentionally supports the small source subset exercised
here and a fixed two-module restore contract. Missing captures, unknown native
capabilities, missing dependencies and absent admission evidence fail rather than
being replaced with guessed values. Catalog registration is an intentional
restore-time operation. This is not a general sandbox or effect analysis for
arbitrary Lain. Hashes check artifact consistency, not cryptographic authorship.

Two focused tests pass 10 assertions covering exact selection, omission of old
executions, hash checks, missing captures/dependencies, unknown capabilities and
missing admission evidence. The successful real trial adds the process,
application-identity, database-discovery and reactive-update evidence above.
Numbers use absolute tolerance 0.00001. Full causal provenance and durable
suspended-state resumption remain separate milestones.

## Reproduction

First complete the documented cumulative catalog experiment and close it. Then,
from the harness root, choose a fresh absolute evidence directory:

```bash
LAIN_SAVED_DATABASE=/absolute/path/cumulative-6-direct/database \
LAIN_EVIDENCE_DIR=/absolute/path/durable-trial \
bash tools/run_catalog_durable.sh
```

The runner copies source into an isolated directory and records source/runtime
revisions, bundle hashes, admitted forms, provider requests/responses, query and
registration events, compiled applications, results and process identities.
Bulk artifacts and database files remain local under ignored
`runtime/durable-20261110/`.
